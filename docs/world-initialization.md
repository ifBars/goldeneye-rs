# Partial world initialization

New Game owns its admitted session, source partition, mission resources and
partial live world on the same CPU worker. Only typed progress snapshots cross
to the window. Back cancels the attempt; shutdown releases the retained owners.

Map binding happens before trigger activation. Each activated map retains one
slot per original serialized ordinal, including filtered and unsupported rows.
Zone selection uses the actual loaded map order, declared bounds and BSP before
callback classification. Host numeric agreement with the Wii remains unverified.

Supported StartPoint construction owns common state, copies original poses,
appends scratch and live membership, then initializes its required map animator.
Animator index zero is valid. Fresh constructor create is denied because the
trigger has no player owner; registration is unmapped. Shared variables and state
flags are initialized, execution slots are empty, and extra scratch stays
explicitly unwritten. This does not execute an invented script or deferred queue.

References resolve through each map's original slots. A filtered target can be
null; an unsupported target stays blocked. The catalog cannot be completed while
required constructors, references or animators remain unsupported. User readiness,
player creation and camera readiness stay false at this checkpoint.

Generic and the supported common-only subtypes use the distinct inactive factory
path. They remain valid owned reference targets and list members while their
activation bit stays clear. Registration stops an absent animator, even if a
selector is serialized; it does not construct that animator. Generic radius and
resource fields have their own derived runtime state, separate from original
properties. A reached unsupported resource lookup retains a staged common object
without publishing it as a registered member or inventing a provider result.
References belonging to a staged object remain unfinished.

The current Tutorial probe retains 196 original slots across two activated maps.
Twenty supported constructor kinds own 194 objects, with 242 resolved references
and no blocked references. Ten members carry the source activation flag; 184 use
the inactive registration path and stop an absent animator. Three StartPoint
animators are initialized. Nine checked type-0 shape selectors are retained,
and four shapes are materialized and transformed. One source-null slot creates no
object, one slot is filtered, and none remain unclassified. These are observations of this
checkpoint, not a full-game denominator or proof of physics/update scheduling.

Factory return status and effective registration status are distinct. The active
relay constructor initially returns status1, then may set a runtime activation
bit during initialization; the callback promotes it to status2. Required animator
requests carry the actual trigger kind. The app supports the proven fresh
StartPoint callback and rejects other reached animator callbacks explicitly.

Range and radius constructors retain original serialized words alongside their
own derived floats/tokens. Their default, scaling and provider rules differ.
Common shape binding addresses the actual map descriptor and retains a checked
type-0 selector before common scratch insertion. Missing reached bytes fail,
while unsupported selector/type scope stays explicit. This branch constructs no
geometry, dimensions, bounds or transforms. Later shape queries remain separate. General host floating-point parity remains unverified.

The dashboard reports actual slot, membership, animator and blocker counts plus
a deterministic fingerprint of the private state. It exports no source payload
arrays, poses, programs or pointers. These component counts are not a percentage
of the game, nor evidence of original-runtime parity.
